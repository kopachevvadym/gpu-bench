# GPU-бенчмарк до тестового завдання UKRLAW

Перевірка двох тез із технічного рішення на реальному залізі:

1. Скільки часу і памʼяті займає один кліп Wan 2.2 I2V A14B (720p, 81 кадр, 5 с) на одній GPU.
2. Що дає sequence parallel (FSDP + Ulysses) на двох GPU без NVLink і яка пропускна здатність NCCL між картами.

## Залізо

| Параметр | Значення |
|---|---|
| Провайдер | RunPod, шаблон PyTorch 2.8.0, CUDA 12.8.1, Ubuntu 24.04 |
| GPU | 2 × NVIDIA RTX PRO 6000 Blackwell Server Edition, 96 ГБ, ліміт 600 Вт |
| Звʼязок між GPU | PCIe 5.0, топологія NODE (без NVLink), P2P дозволено |
| Драйвер, CUDA | 595.91.07, CUDA 13.2 (драйвер); PyTorch 2.8.0+cu128, NCCL 2.27.3, flash-attn 2.8.3 |
| Дата | 28.10.2026 |

## Результати

| Запуск | Повний час, с | Генерація, 20 кроків | с/крок | Пікова памʼять на GPU, ГБ | Пікова потужність на GPU, Вт | Енергія GPU на кліп, Вт·год |
|---|---|---|---|---|---|---|
| 1 GPU (offload_model=True) | 1049 | 16:10 | 48,5 (47 у сталому режимі) | 90,1 | 598 | ≈ 154 (+10 простій другої GPU) |
| 2 GPU, FSDP + Ulysses 2 | 605 | 8:34 | 25,7 | 92,4 | 574 | ≈ 166 (обидві GPU) |

- Прискорення одного кліпу на 2 GPU: **1,73×** за повним часом, **1,89×** за чистою генерацією.
- Пропускна здатність: дві GPU з окремими кліпами дають 2 кліпи за 1049 с (**2,0×**), тобто більше, ніж 1,73× від спільної роботи над одним кліпом, і за ту саму енергію на кліп.
- NCCL all_reduce 256 МБ через PyTorch: **7,2 мс, ≈ 37 ГБ/с** між картами по PCIe.
- Offload на 1 GPU коштує мало: крок у сталому режимі 47 с, а перемикання з high-noise на low-noise експерта додає ≈ 27 с один раз за кліп (крок 9).
- Кліп: 81 кадр, 16 к/с (5 с), 832 × 1104. Wan підганяє співвідношення сторін під вхідне зображення в межах площі 1280 × 720.
- Температура GPU не перевищила 75 °C.

Повний час включає завантаження ваг у памʼять (≈ 35 с на 1 GPU, ≈ 70 с на 2 GPU). Кількість кроків зменшено до 20 (офіційно 40), однаково для обох запусків. Вхідне зображення взято з прикладів Wan 2.2 (`examples/i2v_input.JPG`), тому промпт про юриста на результат майже не вплинув; на час і памʼять зміст кадру не впливає.

Повна таблиця, згенерована `summarize.py`: [`logs/results.md`](logs/results.md). Відео: [`logs/wan_1gpu.mp4`](logs/wan_1gpu.mp4), [`logs/wan_2gpu.mp4`](logs/wan_2gpu.mp4).

## Висновок

Друга GPU прискорює один кліп у 1,7-1,9 раза, але для пропускної здатності вигідніше давати кожній GPU окреме завдання. Ulysses на кількох картах доречний лише для швидкого превʼю одного кліпу. Wan 2.2 A14B займає 90-92 ГБ, тому він працює тільки на картах класу 96 ГБ; карти на 32 ГБ лишаються для LTX, TTS і зображень. Виміряний час кліпу (≈ 1050 с на 20 кроках) на ≈ 22% кращий за консервативну оцінку в технічному рішенні, а енергія GPU на кліп ≈ 0,16 кВт·год.

## Що пішло не так і як виправлено

Три проблеми сумісності, усі повʼязані з новим поколінням Blackwell або пакуванням:

1. **Системна NCCL 2.25.1 з образу** падає на першій операції (`Cuda failure 'invalid argument'`), хоча `nvidia-smi topo -p2p r` показує P2P OK. NCCL 2.27.3 з PyTorch працює. Тому nccl-tests не дали результату, а пропускну здатність виміряно скриптом `ar.py` через `torch.distributed`.
2. **flash-attn** не збирається через `pip install -r` (ізольоване середовище збірки без torch). Виправлено: `pip install flash-attn --no-build-isolation`.
3. **Wan 2.2** при `import wan` тягне модулі speech-to-video і animate із залежністю `decord`, якої немає в основних requirements. Виправлено патчем `patches/wan_optional_imports.diff`: ці імпорти стали необовʼязковими.

## Обмеження

- Тест ішов на ліміті 600 Вт. Карта допускає ліміт 300-600 Вт (`logs/power_limits.txt`), тож 400 Вт із рішення в межах підтримуваного, але швидкість на 400 Вт виміряти не вдалося: `nvidia-smi -pl` у контейнері RunPod повертає `Insufficient Permissions`. Сповільнення на 400 Вт оцінюю в 10-20%, це не вимір.
- Один прогін на конфігурацію, без повторів; розкид не оцінено.
- Один промпт і одне вхідне зображення з прикладів Wan 2.2.

## Як відтворити

```bash
git clone https://github.com/kopachevvadym/gpu-bench && cd gpu-bench
STEPS=20 WORK=/workspace/bench ./run_bench.sh
```

Скрипт сам ставить flash-attn без ізоляції збірки і накладає `patches/wan_optional_imports.diff` на свіжий клон Wan2.2. Потрібно: 2 GPU по ≥ 96 ГБ, ≥ 250 ГБ диска, Python 3.10+. На RunPod прогін зайняв ≈ 1 год 15 хв разом із налагодженням і коштував ≈ $4.

## Файли

- `run_bench.sh`: увесь прогін, від nccl-tests до двох запусків Wan 2.2.
- `ar.py`: вимір all_reduce через NCCL з PyTorch.
- `patches/wan_optional_imports.diff`: патч імпортів Wan 2.2.
- `summarize.py`: зводить логи в таблицю.
- `logs/`: сирі логи, `gpu.csv` (памʼять, потужність, температура щосекунди), `topo.txt`, `versions.txt`, `power_limits.txt`, `results.md`, відео `wan_1gpu.mp4` і `wan_2gpu.mp4`.
